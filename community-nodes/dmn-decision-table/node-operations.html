Node Operations

This document describes every property available in the DMN Decision Table node as seen in the n8n UI.

For complete manual, JSON, and DMN XML configurations, see Table source examples.

The node subtitle displays the decision as ={{$parameter["decisionId"] || "Decision table"}}.

Hit Policy​

FIRST, UNIQUE, ANY, PRIORITY, COLLECT (with SUM / COUNT / MIN / MAX aggregation), RULE ORDER, OUTPUT ORDER. See the README for semantics. PRIORITY and OUTPUT ORDER need output value ordering to differ from FIRST / RULE ORDER.

Rules​

Each rule holds an optional informational Description (builder note, like DMN rule annotations; imported from DMN <description> and never affecting matching), input entries (inputName + cell expression, see cell expressions) and output entries (outputName + value, parsed as JSON except string/date outputs which also accept bare text). In manual and JSON tables, an input with no entry is a wildcard. XML cells are positional and must match the declared column counts exactly; use an explicit empty cell for a wildcard. Every rule must define every output (use null for an empty result). Duplicate entries and references to undeclared inputs/outputs are rejected.
