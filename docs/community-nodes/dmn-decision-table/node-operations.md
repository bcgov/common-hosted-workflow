# Node Operations

This document describes every property available in the DMN Decision Table node as seen in the n8n UI.

For complete manual, JSON, and DMN XML configurations, see [Table source examples](table-source-examples.md).

| Property               | Type            | Required | Default              | Description                                                                                                                                                                                                                                                                                                                                    |
| ---------------------- | --------------- | -------- | -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Table Source           | options         | Yes      | `Build Manually`     | Where the decision table definition comes from (`manual`, `json`, `dmnXml`)                                                                                                                                                                                                                                                                    |
| Decision ID            | string          | No       | —                    | Label shown in the subtitle; also selects the decision when Table Source is DMN XML                                                                                                                                                                                                                                                            |
| Table Version          | string          | No       | —                    | Optional version label. Informational only                                                                                                                                                                                                                                                                                                     |
| Hit Policy             | options         | Yes      | `FIRST`              | How multiple matching rules are resolved. Shown only for manual tables                                                                                                                                                                                                                                                                         |
| Collect Aggregation    | options         | Yes      | `NONE`               | How COLLECT combines matching outputs. Shown only for manual COLLECT tables                                                                                                                                                                                                                                                                    |
| Inputs                 | fixedCollection | No       | —                    | Decision inputs (Name, Type, Value). Empty Value reads from the item JSON by name; a set Value (constant or per-item expression) overrides it. Falsy values like `0`/`false` still apply. Shown only for manual tables                                                                                                                         |
| Outputs                | fixedCollection | No       | —                    | Decision outputs, written to each item. Shown only for manual tables                                                                                                                                                                                                                                                                           |
| Rules                  | fixedCollection | No       | —                    | Rules evaluated top to bottom; empty cells match anything. Shown only for manual tables                                                                                                                                                                                                                                                        |
| Table JSON             | json            | Yes      | —                    | Full table (`hitPolicy`, `inputs`, `outputs`, `rules`, `defaultOutput?`, `aggregation?`, `outputPriorities?`). | DMN XML                | string          | Yes      | —                    | DMN 1.x XML source. Entries override the embedded default; an empty list falls back to it. Shown only for manual tables |
| Default Output (JSON)  | json            | No       | `{}`                 | Same as Default Output Entries but as a JSON object; a non-empty value overrides the embedded default. The node subtitle displays the decision as `={{$parameter["decisionId"] || "Decision table"}}`.

## Hit Policy

`FIRST`, `UNIQUE`, `ANY`, `PRIORITY`, `COLLECT` (with `SUM` / `COUNT` / `MIN` / `MAX` aggregation), `RULE ORDER`, `OUTPUT ORDER`. See the [README](README.md#hit-policies) for semantics. PRIORITY and OUTPUT ORDER need output value ordering to differ from FIRST / RULE ORDER.

## Rules

Each rule holds an optional informational `Description` (builder note, like DMN rule annotations; imported from DMN `<description>` and never affecting matching), input entries (`inputName` + cell `expression`, see [cell expressions](README.md#cell-expressions)) and output entries (`outputName` + `value`, parsed as JSON except `string`/`date` outputs which also accept bare text). In manual and JSON tables, an input with no entry is a wildcard. XML cells are positional and must match the declared column counts exactly; use an explicit empty cell for a wildcard. Every rule must define every output (use `null` for an empty result). Duplicate entries and references to undeclared inputs/outputs are rejected.
