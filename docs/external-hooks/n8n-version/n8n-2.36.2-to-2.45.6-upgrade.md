# n8n 2.45.6 Upgrade — external-hooks Compatibility Report

**Date:** 2026-10-29
**Base image bump:** `n8nio/n8n` `2.36.2` → `2.45.6` (set in `Dockerfile`)
**Scope:** `external-hooks` integration with n8n's compiled runtime internals

---

## Summary

external-hooks has no npm dependency on n8n. It `require()`s a fixed set of n8n's compiled modules from the container at runtime and calls into them (see `src/api/constants/n8n-paths.ts` and [n8n-internals-check.md](./n8n-internals-check.md)). The 2.36.2 → 2.45.6 jump did two things that broke that contract:

1. **Moved four service modules** out of the n8n CLI build (`dist/...`) into a new package, `@n8n/backend-services`. This broke `require()` resolution — n8n crashed on boot.
2. **Changed the `JwtService.sign` signature** and **added a required field to two credential events**. These are behavioral/contract changes that the module-existence guard cannot detect.

All issues are resolved. OIDC login works again, and credential audit events carry the correct name.

---

## What changed in n8n 2.45.6

### 1. Services relocated to `@n8n/backend-services`

Four modules moved from the CLI `dist/` tree into the new `@n8n/backend-services` package (v1.5.5). Same internal sub-paths, same export names — only the package root changed.

| Export                         | Old path (gone in 2.45.6)                               | New path                                                                    |
| ------------------------------ | ------------------------------------------------------- | --------------------------------------------------------------------------- |
| `JwtService`                   | `n8n/dist/services/jwt.service.js`                      | `n8n/node_modules/@n8n/backend-services/dist/services/jwt.service.js`       |
| `CredentialsFinderService`     | `n8n/dist/credentials/credentials-finder.service.js`    | `…/@n8n/backend-services/dist/credentials/credentials-finder.service.js`    |
| `EventService`                 | `n8n/dist/events/event.service.js`                      | `…/@n8n/backend-services/dist/events/event.service.js`                      |
| `WorkflowPublishedDataService` | `n8n/dist/workflows/workflow-published-data.service.js` | `…/@n8n/backend-services/dist/workflows/workflow-published-data.service.js` |

The other 12 modules in the manifest (DI, DB, core, user/auth/credentials/project services, node-mailer, workflow, config, workflow-runner, active-executions) are unchanged.

**Observed symptom:** n8n failed to boot with
`Cannot find module '/usr/local/lib/node_modules/n8n/dist/services/jwt.service.js'`
thrown while loading `/external-hooks/api/hooks.cjs`.

### 2. `JwtService.sign` signature changed

The method now takes a leading **`purpose`** and derives the token's `aud` claim from it internally.

```ts
// Before (effectively):
sign(payload, options)

// After (n8n 2.45.x):
sign(purpose: TokenPurpose, payload: object, options?): string
// audience is set internally: audience = TOKEN_PURPOSES[purpose]
```

If `purpose` is omitted, the arguments shift, `audience` becomes `undefined`, and `jsonwebtoken` throws `"audience" must be a string or array`.

The browser auth-cookie purpose is **`'session'`** (`aud: 'n8n:session'`). n8n's own `AuthService.issueJWT` signs with `sign('session', …)` and verifies with `verify('session', …)`.

**Observed symptom:** after fixing the path, OIDC login failed with
`"audience" must be a string or array` in `OidcLoginCoordinator → createAuthToken → JwtService.sign`.

### 3. `credentials-created` / `credentials-updated` events now require `credentialName`

n8n's `RelayEventMap` added a required `credentialName: string` field to both events. The activity / log-streaming / telemetry relays destructure it and record it as the audit entry's `resourceName`.

**Impact:** not a crash. Credentials created/updated through external-hooks were logged with `resourceName: undefined` — an audit-fidelity regression.

### 4. Verified unchanged (no action needed)

| Service                        | Method(s) used by external-hooks                                                  | Why it's safe                                                                 |
| ------------------------------ | --------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `CredentialsFinderService`     | `findCredentialsForUser(user, scopes)`, `findCredentialForUser(id, user, scopes)` | Only added an optional trailing `options` param; positional args still align. |
| `WorkflowPublishedDataService` | `getPublishedWorkflowData(workflowId)` → `{ workflow, publishedVersion }`         | Signature and return shape unchanged.                                         |

## What we changed in external-hooks

### A. `src/api/constants/n8n-paths.ts` — repointed the four moved modules

- Added a private `N8N_BACKEND_SERVICES_DIST` base constant for the new package's `dist` root (deliberately **not** named `*_PATH`, so the contract test does not treat it as a required module).
- Repointed `N8N_JWT_SERVICE_PATH`, `N8N_CREDENTIALS_FINDER_SERVICE_PATH`, `N8N_EVENT_SERVICE_PATH`, and `N8N_WORKFLOW_PUBLISHED_DATA_PATH` at `@n8n/backend-services`.
- Expected export names in `N8N_INTERNAL_MODULES` were unchanged (classes kept their names).

### B. `src/api/services/jwt.ts` — new `sign` signature in the wrapper

- Updated the wrapper `JwtService` and its `BaseJwtService` structural type from the old 2-arg form to the new `(purpose, payload, options)` form, forwarding `purpose` to the real n8n service.
- Introduced a narrow `TokenPurpose = 'session'` type (the only purpose external-hooks mints).

### C. `src/api/helpers/n8n-oidc.ts` — pass the `'session'` purpose

```ts
// Before:
return jwtService.sign(payload, { expiresIn: '7d' });
// After:
return jwtService.sign('session', payload, { expiresIn: '7d' });
```

### D. `src/api/services/n8n-credentials.service.ts` — emit `credentialName`

- `create` → `credentialName: dto.name`
- `update` → `credentialName: prepared.name ?? existing.name`

## Follow-ups / recommendations

- **Re-verify on every base-image bump.** The startup guard (`src/verify-n8n-internals.ts`, manifest in `n8n-paths.ts`) catches moved/renamed modules, but **not** signature or payload changes (issues #2 and #3 above slipped past it).
- **Consider contract tests** that invoke each wrapped method against a minimal stub (or pin the expected n8n version), so call-shape drift fails loudly at test time rather than at runtime.
- **Other `@n8n/backend-services` consumers:** if future code calls into `EventService` or `WorkflowPublishedDataService` beyond what's listed here, re-check their signatures — that package is now a moving target across releases.
